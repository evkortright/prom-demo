# Session Handoff — 2026-10-01

## What this project is

`prom-demo` is a tool that normalizes raw Prometheus metrics to OpenTelemetry
semantic conventions before indexing into Elasticsearch, and converts Grafana
dashboards to Kibana equivalents automatically.

It solves a real migration problem: organizations running Prometheus + Grafana
who want to move to Elastic Observability. Without normalization, every
dashboard query must be rewritten by hand. With it, the conversion is largely
automated.

## Critical technical facts (don't re-learn these)

### 1. TSDS and TS command
The data stream `metrics-prometheusreceiver.otel-default` is automatically
a TSDS via the `metrics-otel@template` built-in Elastic template. Use the
`TS` source command (not `FROM`) for time-series queries:

```esql
TS metrics-prometheusreceiver.otel-default
| WHERE service.name == "node-exporter"
| WHERE `system.cpu.state` == "idle"
| STATS avg_idle = AVG(RATE(`metrics.system.cpu.time`))
```

### 2. Two field representations
The OTel exporter creates two versions of each metric:
- `system.cpu.time` — normalized attribute (type: double) — use for WHERE filters
- `metrics.system.cpu.time` — metric value (type: counter_double) — use with RATE()

### 3. cumulative_to_delta scope
Only converts histograms (strict name match). Counters stay cumulative so
they land as counter_double and support RATE(). The four histograms:
- http_request_duration_seconds
- grpc_server_handling_seconds
- db_query_duration_seconds
- go_gc_duration_seconds

### 4. counter_double and RATE()
RATE() requires counter_double type. Always use `metrics.` prefixed fields
with RATE(). Regular `system.cpu.time` is double and won't work with RATE().

### 5. ES|QL field name escaping
Field names with dots that start with a number need backticks:
- `` `system.cpu.load_average.1m` `` — needs backticks (starts with digit after dot)
- `system.cpu.state` — no backticks needed

## Three-tier conversion architecture

**Tier 1 — Deterministic:** Rule-based, no AI. Fast, reliable. Current state.

**Tier 2 — AI-assisted (NEXT TASK):** LLM proposes translations for complex
PromQL expressions. Always explains approximations. Human reviews.

**Tier 3 — Human-only:** Flags patterns with no reasonable automated
equivalent (subqueries, recording rules).

## Immediate next task: Tier 2 AI-assisted translation

### The two patterns to tackle first

These come from the CPU Basic panel (Node Exporter Full, panel id 77).
Targets A/B/C/F already convert in Tier 1. These two need AI:

**Target D — regex filter + sum without:**
```
avg(sum without(mode)(rate(node_cpu_seconds_total{mode=~".*irq"}[$__rate_interval])))
```
Legend: "Busy IRQs"
Intent: sum softirq + irq together, average across cores

Expected ES|QL translation:
```esql
TS metrics-prometheusreceiver.otel-default
| WHERE @timestamp >= NOW() - 1 hour
| WHERE service.name == "node-exporter"
| WHERE `system.cpu.state` IN ("irq", "softirq")
| STATS cpu_rate = AVG(RATE(`metrics.system.cpu.time`))
    BY BUCKET(@timestamp, 30 seconds)
```

**Target E — complex exclusion:**
```
avg(sum without(mode)(rate(node_cpu_seconds_total{
  mode!='idle',mode!='user',mode!='system',
  mode!='iowait',mode!='irq',mode!='softirq'
}[$__rate_interval])))
```
Legend: "Busy Other"
Intent: everything that doesn't fit named categories

Expected ES|QL translation:
```esql
TS metrics-prometheusreceiver.otel-default
| WHERE @timestamp >= NOW() - 1 hour
| WHERE service.name == "node-exporter"
| WHERE `system.cpu.state` NOT IN
    ("idle", "user", "system", "iowait", "irq", "softirq")
| STATS cpu_rate = AVG(RATE(`metrics.system.cpu.time`))
    BY BUCKET(@timestamp, 30 seconds)
```

### What the AI prompt needs to do

Given a PromQL expression the Tier 1 parser can't handle, the AI:
1. Receives: the PromQL expression, the field mapping table, ES|QL constraints
2. Produces: a valid ES|QL query using TS command and RATE() on metrics.* fields
3. Explains: what changed and what any approximations mean
4. Returns: structured JSON with {esql, explanation, confidence, tier}

Key constraint: AI must always use `TS` (not `FROM`) and `metrics.` prefixed
fields with `RATE()`. The prompt must make this explicit.
